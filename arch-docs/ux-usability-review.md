# UX/사용성 검토 리포트

- 작성일: 2026-08-29
- 대상 버전: 2.9.1
- 검토 범위: 팝업(`popup.html`/`popup.js`), 설정(`settings.html`/`settings.js`), 페이지 목록(`pages-list.html`/`pages-list.js`), 인페이지 컨트롤(`content-scripts/controls.js`), 미니맵(`content-scripts/minimap.js`), 복원 로직(`content-scripts/content.js`), 컨텍스트 메뉴(`background/context-menu.js`), 로케일(`_locales/`)

## 우선순위 높음

### 1. 복원에 실패한 하이라이트가 조용히 사라짐 — 완료 (#113)

`content-scripts/content.js`의 복원 경로(`processRestoreGroups()` → `restoreQuoteGroups()` / `restoreLegacyGroup()`)에서 quote 셀렉터와 레거시 span 복원이 모두 실패하면 `debugLog`만 남고 사용자에게는 아무 표시가 없었다. 팝업 목록은 스토리지 기준으로 그리기 때문에, 팝업에는 하이라이트가 보이는데 페이지에는 없는 상태가 된다. 사용자 입장에서는 "확장이 고장났다"로 인식되는 가장 흔한 시나리오.

**적용한 것:**
- 팝업 항목에 "이 페이지에서 찾을 수 없음" 표시 + 항목별 **다시 찾기** 버튼. 점프 어피던스(`role="button"`, 탭 포커스)는 제거해서 눌러도 아무 일 없는 상태를 없앴다
- 복원 실패 그룹에 대한 1회 지연 재시도. 늦게 도착하는 콘텐츠(지연 로딩 댓글, 펼쳐진 섹션, 아직 정착 중인 SPA 뷰)를 회수한다
- 페이지가 아직 복원 중이면 팝업은 표시를 **보류**한다. 판단이 안 될 때는 목록을 건드리지 않는 쪽이 기본값

**만들지 않기로 한 것:** "복원 실패 개수를 미니맵 또는 액션 뱃지로 알림"은 폐기한다. 사용자가 그 숫자를 보고 할 수 있는 일이 없다 — 몇 개가 실패했는지 알아도 어느 것인지, 무엇을 해야 하는지가 없으면 불안만 남는다. 개수를 세는 대신 **항목별 상태에 행동 수단을 붙이는** 쪽을 택했다.

지연 재시도는 과거 `bc85b6b`에서 도입했다가 저사양 PC·태블릿 부하 피드백으로 `b743c5d`에서 되돌린 이력이 있다. #111/#112로 복원 패스 비용을 줄인 뒤에야(6배 CPU 스로틀 기준 배치당 1457ms → 112ms) 다시 넣을 수 있었다. `MutationObserver`는 일반적인 페이지 변화에도 복원을 다시 돌리게 되므로 의도적으로 쓰지 않았다.

### 2. 하이라이트 목록에서 해당 위치로 점프가 안 됨 — 팝업은 완료 (#110), 페이지 목록은 남음

팝업의 하이라이트 항목은 클릭하면 해당 하이라이트로 스크롤한다(#110). 미니맵의 `scrollToHighlight()`(`minimap.js`)를 재사용했다.

남은 것: 페이지 목록(`pages-list.js`)의 "Open Page"는 여전히 페이지만 열 뿐 특정 하이라이트로 이동하지 못한다.

### 3. 삭제 UX: 매번 confirm 모달, undo 없음

개별 하이라이트 하나 지우는 데도 확인 모달이 뜬다(`popup.js` 삭제 버튼 핸들러). 개별 삭제는 "즉시 삭제 + 토스트로 실행 취소" 패턴이 마찰이 훨씬 적다. 반대로 "Delete All Highlights"(팝업)와 "Delete All Pages"(페이지 목록)는 복구 불가인데도 모달 한 번이 전부다.

**개선안:**
- 개별 삭제: confirm 제거, 삭제 후 undo 토스트
- 전체 삭제: 삭제 전 "내보내기" 백업 제안 한 줄 추가

### 4. 데스크톱에서 하이라이트까지 2번 클릭

선택 → 아이콘 클릭 → 팔레트에서 색 클릭의 2단계 인터랙션. 경쟁 확장 대부분은 선택 즉시 색상 바를 띄우거나 "마지막 사용 색으로 원클릭"을 지원한다.

**개선안:**
- 아이콘 클릭 시 마지막 사용 색으로 즉시 하이라이트
- 팔레트는 호버(데스크톱)나 롱프레스(모바일)로 열기
- 단축키(슬롯 1~5)의 발견 가능성 개선과 병행

### 5. 온보딩 부재

`onInstalled` 시 안내 페이지가 없고 팝업 설명도 한 줄뿐이다. "텍스트를 드래그하면 아이콘이 나타난다", 컨텍스트 메뉴·단축키의 존재를 처음 사용자가 알 방법이 스토어 설명뿐.

**개선안:**
- 설치 직후 간단한 가이드 탭 열기
- 또는 팝업의 빈 상태(no-highlights) 영역에 사용법 안내 삽입

## 우선순위 중간

### 6. 인페이지 컨트롤의 키보드/스크린리더 접근성 부재

색상 버튼, 삭제 버튼, 선택 아이콘이 전부 `<div>`이고(`controls.js`) `role`, `tabindex`, `aria-label`이 없어 키보드로는 조작 불가. 팝업의 삭제 버튼도 `<span>`이라 포커스가 가지 않는다.

### 7. 팝업 삭제 버튼이 너무 작음

16×16px에 글자 "x"를 아이콘으로 사용. 최소 24px 히트 영역과 SVG 아이콘 권장. 하이라이트 텍스트가 80자에서 잘리는데 전체 텍스트를 볼 방법(title 툴팁조차)이 없다.

### 8. 페이지 목록 툴바의 위험 버튼 배치

아이콘 전용 버튼 5개가 나란히 있고 "전체 삭제"(휴지통)가 "새로고침" 바로 옆(`pages-list.html` 툴바). 파괴적 액션은 more 메뉴로 옮기거나 간격을 두는 게 안전하다.

### 9. 커스텀 색상 피커에 hex 입력이 없음

HSV 슬라이더와 프리셋만 있어 브랜드 색상 등 정확한 값을 지정할 수 없다. 또한 커스텀 색을 추가해도 바로 적용되지 않고 팔레트에서 다시 클릭해야 한다.

### 10. 단축키 변경 동선

설정 화면이 `chrome://extensions/shortcuts` 주소를 텍스트로만 안내한다. Chrome에서는 `tabs.create`로 해당 페이지를 여는 버튼을 넣을 수 있다(Firefox는 불가하니 분기 필요).

### 11. URL 완전일치 키의 함정

하이라이트가 `tab.url` 전체(쿼리스트링, 트래킹 파라미터, fragment 포함)를 키로 저장되므로, `?utm_source=...`가 붙어 재방문하면 같은 문서인데 하이라이트가 없는 것으로 보인다. 최소한 fragment 제거, 나아가 주요 트래킹 파라미터 정규화 검토 가치가 있다.

### 12. 네이밍 불일치

확장 이름은 "Marks: 텍스트 하이라이터"인데 팝업 제목은 "텍스트 하이라이터". 브랜드 노출을 위해 팝업에도 "Marks" 사용이 일관적이다.
