# 하이라이트 텍스트 색 검토

작성일: 2026-09-16  
대상 저장소: `text-highlighter`

---

## 1) 배경

하이라이트 텍스트는 `styles.css`의 `color: #000 !important`로 검정에 고정되어 있었다.
그래서 하이라이트 색을 어둡게 고르면 글자가 거의 보이지 않았다. 애드온 스토어 리뷰에도
"텍스트 색을 바꿀 수 있으면 좋겠다"는 요청이 있었다.

현재 UX(선택 바와 하이라이트 바의 색 스트립, `+` 피커, 단축키 슬롯, 컨텍스트 메뉴)에는
텍스트 색을 따로 고를 자리가 마땅하지 않다. 이 문서는 선택지를 검토한 기록이다.

---

## 2) 과거 이력

| 시점 | 커밋 | 내용 |
|---|---|---|
| 2025-05-11 | `308c5c1` | 배경 YIQ 밝기 > 128이면 검정, 아니면 흰색. `textColor`를 하이라이트에 저장 |
| 2025-05-11 | `9ca70a7` | 위 로직 제거 |
| 2025-06-08 | `66249d4` | `.text-highlighter-extension { color: #000 }` 추가 (사이트 글자색 상속 차단) |

제거 이유는 커밋에 남아 있지 않다. 작성자 확인 결과, **판정이 눈으로 보기에 어울리지 않아서**
검정이 낫다고 판단했다.

원인은 기준값이었다. YIQ 128은 검정이 충분히 읽히는 중간 톤까지 흰색으로 바꾼다.

| 배경 | 검정 대비 | 흰색 대비 | YIQ 128 | WCAG 높은 쪽 | 채택 기준 |
|---|---|---|---|---|---|
| `#E74C3C` (피커 프리셋) | 5.5 | 3.8 | 흰색 | 검정 | 검정 |
| `#808080` | 5.3 | 3.9 | 흰색 | 검정 | 검정 |
| `#9B59B6` (피커 프리셋) | 4.5 | 4.7 | 흰색 | 흰색 | 검정 |
| `#666666` | 3.7 | 5.7 | 흰색 | 흰색 | 검정 |
| `#555555` | 2.8 | 7.5 | 흰색 | 흰색 | 흰색 |
| `#1E3A8A` | 2.0 | 10.4 | 흰색 | 흰색 | 흰색 |

채도 높은 중간 톤에 흰 글씨를 얹으면 번져 보이고 형광펜보다 스티커처럼 보인다.
"대비가 더 높은 쪽"을 고르는 WCAG 방식도 `#9B59B6`, `#666666`에서 같은 문제가 난다.

## 3) 검토한 선택지

| 방식 | UX 영향 | 데이터 변경 | 판단 |
|---|---|---|---|
| A. 자동 대비 | 없음 | 없음 (배경에서 계산) | **보수적 기준으로 채택** |
| B. 팔레트 색마다 텍스트 색 지정 | 바는 그대로, 설정과 `+` 피커 확장 | 팔레트·그룹에 선택 필드 `textColor` | 향후 과제 |
| C. 바에 텍스트 색 버튼/스트립 | 탭 한 번 추가, 모바일 바는 이미 꽉 참 | 그룹에 `textColor` | 비권장 |
| D. 텍스트만 칠하는 스타일(배경 없음, 밑줄 등) | 새 모드 개념 | 큼 | 범위 밖 |

같은 색조의 어두운/밝은 틴트를 글자색으로 쓰는 방식도 비교했다. 톤은 부드럽지만
모든 색에 적용하면 기존 사용자의 화면이 전부 달라지므로 채택하지 않았다.

## 4) 결정: 보수적 자동 전환

- **기본은 검정.** 검정 글자의 대비가 3:1(WCAG 큰 글자 최소 기준) 미만일 때만 흰색으로 바꾼다.
  상대 휘도로는 L < 0.1에 해당한다.
- 기본 팔레트 5색과 `+` 피커 프리셋 20색은 **모두 검정 그대로다.** 바뀌는 것은 검정이 사실상
  읽히지 않는 어두운 커스텀 색뿐이다.
- 파싱할 수 없는 색 값(예: import된 `yellow`)은 검정으로 둔다. 기존 동작과 같다.

### 구현

- `content-scripts/color-core.js`
  - `highlightTextColor(background)`: `'#000'` 또는 `'#fff'` 반환
  - `paintHighlight(element, color)`: 배경을 칠하고, 흰색이 필요할 때만 인라인 커스텀 속성
    `--th-highlight-text`를 설정한다. 필요 없으면 제거한다.
- `styles.css`: `color: var(--th-highlight-text, #000) !important`
  - 스타일시트의 `!important` 때문에 인라인 `style.color`는 적용되지 않는다. 그래서 변수로 넘긴다.
- 색을 칠하는 세 곳이 모두 `paintHighlight`를 거친다.
  - 새 하이라이트: `content-core.js`의 `createNewSpan`
  - 복원: `content.js`
  - 색 변경: `content.js`의 `changeHighlightColor`
- 두 manifest에서 `color-core.js`를 `content-core.js` 앞으로 옮겼다.
- **텍스트 색은 저장하지 않는다.** 렌더링할 때마다 배경에서 계산하므로 저장 형식, import/export,
  동기화, 마이그레이션에 영향이 없다. 2025-05 구현이 `textColor`를 저장해 복잡해졌던 점을 피한다.

### 알려진 한계

- 하이라이트 안의 링크처럼 사이트 CSS가 직접 색을 지정한 자식 요소는 여전히 사이트 색을 쓴다.
  어두운 배경 위의 파란 링크는 읽기 어려울 수 있다. `* { color: inherit }`로 덮으면 링크가 링크처럼
  보이지 않게 되므로 적용하지 않았다.
- `rgba()`의 알파는 무시한다. 반투명 배경은 페이지 배경과 섞여 실제보다 밝아 보일 수 있다.
  팔레트는 불투명 hex만 만들기 때문에 import 데이터에서만 생기는 경우다.

## 5) 향후 과제: 팔레트 색마다 텍스트 색 지정 (B)

리뷰에서 요청한 "원하는 글자색"은 자동 전환으로 해결되지 않는다. 요청이 계속되면 B를 진행한다.

### 핵심 원칙

텍스트 색을 **따로 고르는 동작을 만들지 않는다.** 팔레트 색 하나를 "배경+글자" 한 쌍으로 본다.
그러면 원클릭, 단축키 슬롯, 컨텍스트 메뉴, 모바일 바가 지금 흐름 그대로 동작한다.

### UI 제안

- 하이라이트 바와 선택 바의 색 버튼에 작은 `A`를 해당 텍스트 색으로 표시해 조합이 보이게 한다.
- 설정 페이지 커스텀 색 행에 `Aa` 텍스트 색 선택을 추가한다. 선택지는 자동/검정/흰색/직접 선택이다.
- `+` 피커 미리보기를 `Aa` 샘플로 바꾸고 자동/검정/흰색 3단 토글만 둔다. 전체 색 선택은 설정 페이지에만 둔다.

### 데이터

- `textColor`는 선택 필드다. 없으면 자동(위 4장의 규칙)이므로 기존 데이터와 호환된다.
- 하이라이트는 팔레트 id가 아니라 값으로 저장된다. 그래서 그룹에도 `textColor`를 저장해야 한다.
- `shared/import-export-schema.js`의 `normalizeHighlightGroup`은 알려진 필드만 골라 새 객체를 만든다.
  `textColor`를 추가하지 않으면 import할 때 조용히 사라진다.

### 결정이 필요한 점

팔레트의 고유 키는 현재 **배경 hex**다. 이 키를 "배경+텍스트 쌍"으로 바꿀지 정해야 한다.
바꾸지 않으면 같은 노랑에 검정 글자와 빨강 글자를 둘 다 둘 수 없다. 이 키를 쓰는 곳은 다음과 같다.

- 중복 검사: `background/settings-service.js`의 `addCustomColor`, `updateCustomColor`
- 동기화 병합: `background/sync-service.js` (`customColors` 병합)
- 마지막 사용 색: `content-scripts/color-core.js`의 `resolveLastUsedColor`
